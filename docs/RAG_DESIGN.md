# RAG 파이프라인 설계문서 — 법정감염병 안내 도우미

## 1. 전체 흐름

```
[색인 시점: scripts/build_index]
 감염병포털 목록 CSV(133) ──► 항목 텍스트 ──► disease_meta (1건 = 1청크, ID = inf_0001…)
 위키백과 항목 문서(선택 --prefetch-docs) ─► 섹션 → 글자 수 청킹 ─┐
 검역관리지역 API·감염병포털 통계 ──► 감염병별 레코드 문서 ─────────┴► disease_docs

[질문 시점: LangGraph retrieve → generate]
 retrieve: 메타 청크 조회(ID) → 프롬프트 1 검색어 → 위키 검색 → 프롬프트 2 선별 → 본문 수집·청킹·색인
           → disease_docs에서 질문 유사도 Top-k (disease_id 필터) → 병합·중복 제거·번호
 generate: 프롬프트 3 (근거만 사용, [근거 n]) → 본문에서 인용 번호 추출 → 인용된 근거만 화면에
```

## 2. 두 Vector DB 컬렉션과 메타데이터

| 컬렉션 | 단위 | 청크 ID | 메타데이터 |
| --- | --- | --- | --- |
| `disease_meta` | 감염병 1건 = 1청크 | `inf_0021` | disease_id, disease_name, grade(int), group, kcd, department, surveillance, report_deadline, scope_환자/의사환자/병원체보유자(bool), source_type=meta, source_url, wiki_title, wiki_url |
| `disease_docs` | 외부 문서 청크 | `inf_0021:wiki-12345:0003`, `inf_0057:kdca-quarantine-inf_0057:0000` | disease_id, disease_name, doc_id, title, section, **source_type**(wiki / public_api / public_stats), source_label, source_url, license, query, collected_at, seq |

- **왜 둘로 나눴나**: 메타데이터는 "어떤 감염병인가"(항목 찾기·조건 탐색·급수 같은 정확한 사실), 외부 문서는 "그 감염병에 대해 무엇이 쓰여 있나"(설명·근거)로 쓰임과 검색 방식이 다르다.
  메타는 ID로 바로 꺼내고(검색 없이 항상 [근거 1]), 조건 탐색에서는 grade·scope 필터 + 유사도로 찾는다. 문서는 감염병 필터를 건 유사도 검색만 한다.
- **청크 ID**: 같은 문서를 여러 감염병이 수집해도 서로 덮어쓰지 않게 `disease_id:doc_id:순번`. 재색인은 (감염병, 문서) 단위로 지우고 넣어 청크 설정을 바꿔도 낡은 청크가 남지 않는다 (F2002).
- **청크 머리말**: `[감염병: 홍역 | 문서: 홍역 바이러스 | 섹션: 전파]` — 잘린 조각도 어느 감염병·문서인지 검색에 걸리게.

## 3. 수집 · 청킹 · 색인 순서

1. **항목 텍스트 (F2001)**: CSV 1행 → `[법정감염병] 이름 / 급수(감시 방법) / 급수 기준 / 신고 시기 / 신고 범위 / KCD / 담당부서 / 위키 요약 400자`. 법령상 급수 기준 문장을 넣어 "즉시 신고하는 감염병" 같은 조건 질문에도 걸리게 했다.
2. **위키 제목 해석**: 감염병명 → `page.exists` → 괄호·띄어쓰기 변형 → 약어 → 검색. 동음이의 문서는 제외, 잘못 잡힌 것은 `config/wiki_title_overrides.json`.
3. **질문 시 수집 (F2003·F2004)**: 프롬프트 1 검색어 → 검색어마다 위키 후보 5개(동음이의·항목 자체 문서 제외) → 프롬프트 2가 최대 2개 선별 → 본문 저장(`pages/<pageid>.json`) → 섹션별 청킹·색인. 검색어 결과(선택·버림)는 `query_cache.json`에 저장해 같은 검색어는 다시 부르지 않는다 (NF2002).
4. **청킹**
   - 위키: `RecursiveCharacterTextSplitter`, 구분자 `\n\n → \n → ". " → "다. " → 공백`, 섹션별로 먼저 나누고 각주·외부 링크·같이 보기 등은 버린다.
   - 공공데이터 레코드 (F2016): 글자 수로 자르지 않고 **섹션 = 청크**. "감염병 · 기준일 · 값"이 한 덩어리여야 근거로 쓸 수 있기 때문 (자르면 숫자와 감염병 이름이 다른 청크로 갈라짐). 지정 국가가 40개를 넘으면 40개국씩 나누고 머리말(감염병·기준일·국가 수)을 반복.
5. **속도 정책** (NF2001): 앱 기본은 `collect_policy: background` — 이미 모은 위키 문서가 있으면 바로 답하고 이번 질문용 수집은 답한 뒤 배경에서. 처음 묻는 감염병은 LLM 없이 항목 자체 문서만 바로 색인. 검증 스크립트는 `--policy always`로 매번 수집 과정을 보여 준다.

## 4. 검색 결과 병합과 중복 제거

`rag/graph.py build_evidence`
1. 메타데이터 청크를 항상 맨 앞 [근거 1]로 고정 (급수·신고 기준은 메타 우선, 프롬프트 3 규칙 4).
2. 외부 문서 Top-k 청크를 순서대로 붙이되 **청크 ID**가 같거나, 머리말을 뺀 **본문 해시**가 같으면 버린다 (다른 감염병으로 같은 문서를 수집한 경우 등).
3. 남은 순서대로 1부터 번호. 여행 전 안내(F2010)도 같은 규칙: 감염병마다 메타 → 검역 레코드 → 위키 청크 2개.

## 5. 프롬프트 (출력 형식 고정)

| 프롬프트 | 역할 | 입력 | 출력 |
| --- | --- | --- | --- |
| 1 검색어 추출 | 감염병 역학 전문가: 위키 검색어 | 항목 텍스트, 질문, 최대 개수 | `{"queries": ["…", "…"]}` (2~6단어 명사구, 감염병 이름 반복 금지) |
| 2 후보 선별 | 공중보건 자료 검토자: 본문을 받기 전에 버릴 문서 결정 | 감염병, 질문, 검색어, 후보 제목·요약 | `{"selected": ["c1", "c3"]}` (동명이인·영화·지명 제외) |
| 3 답변 생성 | 공중보건 안내원: 근거만 사용 | 감염병, 질문, `[근거 n] (출처 유형) 제목\n본문` | 마크다운 `### 핵심 답변` + 해당 카테고리만 (`초기 증상 / 전체 증상 / 잠복기 / 치사율·중증도 / 전염성·전파 경로 / 발생 지역 / 치료 / 예방 / 신고·관리`), 문장마다 `[근거 n]`, 확인 안 되면 "제공된 문서에서 확인되지 않습니다", 합니다체 |
| (조건 탐색) | 후보 정보만으로 조건을 모두 만족하는 것만 | 조건, 후보 목록 | `{"matches": [{"id", "reason"}]}` |
| (여행 전 안내) | 여행 안내원: 감염병별 전파 경로·예방·귀국 후 할 일 | 나라, 기준일, 근거 | `### 핵심 답변` + `### 감염병` 글머리표마다 `[근거 n]` |

JSON 출력은 코드 블록·앞뒤 문장이 섞여도 `rag/parsing.parse_json`이 꺼내고, 실패하면 그 단계만 건너뛴다(수집 없이 답변).

## 6. 청크 크기 · 중복 · Top-k를 정한 이유

| 설정 | 값 | 이유 | 바꿨을 때 (검증 5·6·16) |
| --- | --- | --- | --- |
| chunk_size | 1000자 | 위키 한 섹션(증상·전파 등)의 한두 문단이 한 청크에 들어가 답에 필요한 문맥이 끊기지 않음. 임베딩 입력 한도보다 충분히 작음 | 500/100으로 줄이면 청크 수가 늘고(실측 `evidence/05_*`) 근거 하나에 담긴 내용이 짧아져, 같은 Top-k로는 다루는 범위가 좁아짐 |
| chunk_overlap | 200자 | 문장 중간에서 잘려도 앞 청크의 마지막 1~2문장이 다음 청크에 남게 | 0이면 경계에 걸친 문장(예: 잠복기 수치)이 반쪽씩 갈라짐 |
| top_k | 5 | 메타 1 + 문서 5 = 근거 6개. 프롬프트 길이·답 생성 시간(스트리밍 첫 글자 ~1s)과 근거 다양성의 균형 | 3이면 근거가 한두 문서에 몰리고, 8이면 관련이 낮은 청크까지 들어가 프롬프트가 길어짐 (같은 질문 비교 `evidence/06_*`) |
| search_type | similarity (기본), mmr (F2014) | 질문이 좁으면 유사도로 충분 | MMR(fetch_k 30, λ 0.5)은 같은 문서의 비슷한 섹션이 몰리는 것을 줄여 문서 종류가 늘어남 (`evidence/16_*`) |
| max_queries / 후보 / 선별 | 3 / 5 / 2 | 검색어당 위키 호출과 LLM 선별 비용을 묶어 두기 위해 | 늘리면 근거는 풍부하지만 수집 시간이 비례해 증가 |

## 7. 답변에 근거를 표시하는 방식

- 본문: 문장·글머리표 끝 `[근거 1, 3]` (회색 작은 글씨).
- 근거 목록: **본문에 실제로 인용된 번호만** 접는 칸에 표시. 각 줄 = 출처 종류 배지(항목 메타데이터 / 위키백과 / 공공데이터 API / 공공 통계) + 번호 + 제목/섹션 + 출처 이름 + 원문 링크. 접는 칸 제목에도 종류를 요약 ("근거 3건 · 위키백과 / 항목 메타데이터").
- 인용이 없으면 "인용된 근거가 없습니다. 제공된 문서로 확인되지 않는 내용일 수 있습니다" 안내.
- 진행 상태: 검색어 → 위키 검색/이미 수집한 검색어 → 새로 색인한 문서 제목 → 근거 검색 → 답변 생성, 배경 수집 결과는 다음 답변에 표시.

## 8. 도메인 특화 기능을 이렇게 설계한 이유 (F2010)

감염병 정보가 실제로 필요해지는 대표 상황은 **해외여행 전**이다. 그래서 홈을 "나라별 주의 감염병" 지구본으로 만들고,
나라를 누르면 질병관리청 검역관리지역 지정 감염병을 보여 준다. 여기에 **여행 전 안내**를 붙여 그 나라의 검역감염병마다
전파 경로·예방법·귀국 후 할 일을 근거와 함께 정리한다.
- 근거: 검역관리지역 레코드(지정 사실·기준일) + 항목 메타데이터(급수·신고) + 이미 색인된 위키 청크(전파·예방).
- 같은 규칙: 근거에 없는 내용은 쓰지 않고, 전파·예방 근거가 없는 감염병은 "확인되지 않습니다"로 둔다.
- 연령별 알아보기·상세보기의 통계는 공공 통계 레코드 문서로도 색인해, 챗봇에서 "수두는 어느 연령대에 많나요?"에 근거를 댈 수 있다.

## 9. 선택의 이유, 겪은 문제와 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| GMS 임베딩 400 "Unknown parameter: input" | LangChain이 토큰 ID 배열을 보내는데 프록시가 원문만 받음 | `check_embedding_ctx_length=False` + `encoding_format=float` (프록시일 때 자동) |
| 위키 제목이 엉뚱한 문서로 잡힘 (동음이의·영화) | 감염병명과 위키 제목 불일치 | 존재 확인 → 변형 → 약어 → 검색 순서, 동음이의 제외, 수동 보정 파일 |
| 각주·외부 링크가 근거로 걸림 | 섹션 구분 없이 자름 | 섹션별 청킹 + 불필요 섹션 제외 |
| 같은 문서가 근거에 두 번 | 여러 감염병으로 같은 문서 수집 | 청크 ID + 본문 해시 중복 제거 |
| 답변 18.5초 | 질문마다 LLM 5회·위키 7회가 순서대로 | 배경 수집·병렬화·스트리밍·문서 미리 색인 → 4.6초, LLM 1회 ([PERFORMANCE.md](PERFORMANCE.md)) |
| 병렬 수집 중 파일 쓰기 충돌 | 같은 임시 파일 이름 | 임시 파일 이름에 uuid, 캐시 쓰기 잠금 |
| GMS 사용 한도 초과(429) | 측정 반복 | 화면에 한도 안내(추적 정보 없이), 측정 스크립트는 결과를 저장하고 이어서 |
| 공공데이터 문서가 '이미 모은 문서'로 세어져 위키 수집을 건너뜀 | 빠른 경로 판단이 문서 수 전체 기준 | 위키 문서 수만 세도록 (`docs_count(did, "wiki")`) |
| 조건 탐색 결과에 조건과 다른 항목이 섞일 수 있음 | LLM 판정에만 의존 | 급수·신고 범위를 규칙으로 뽑아 메타데이터 필터 + LLM 결과 재대조 |
