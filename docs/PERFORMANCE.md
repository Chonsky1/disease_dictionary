# 챗봇 답변 시간 줄이기

## 1. 시간을 어디에 쓰는가 (질문 1개)

기존 방식(`baseline`)은 질문마다 아래를 **차례로** 한다.

| 단계 | 호출 | 비고 |
| --- | --- | --- |
| 검색어 추출 | LLM 1회 | 프롬프트 1 |
| 항목 문서 수집 | 위키 1회 + 임베딩 | 처음 묻는 감염병일 때 |
| 검색어별 수집 (최대 3개) | 위키 검색 3회 + LLM 선별 3회 + 위키 본문 최대 6회 + 임베딩 | 처음 쓰는 검색어일 때 |
| 근거 검색 | 임베딩 1회 | |
| 답변 생성 | LLM 1회 | 답이 다 만들어진 뒤에야 화면에 나옴 |
| (화면) 대화 요약 | LLM 1회 | 답변 뒤에 |

처음 묻는 감염병이면 LLM 최대 6회가 줄지어 일어나고, 화면에는 마지막에 한꺼번에 나온다.

## 2. 줄이는 방법 (모두 `config/rag_settings.json`에서 켜고 끔)

| 방법 | 설정 | 무엇이 줄어드나 |
| --- | --- | --- |
| 수집 병렬화 | `parallel_collect: true` | 항목 문서를 검색어 추출과 동시에, 검색어별 검색·선별·본문을 동시에 → 수집 단계가 가장 느린 검색어 하나만큼 |
| 답변 스트리밍 | `stream_answer: true` | 총 시간은 같지만 **첫 글자**가 바로 나와 체감 대기 시간이 크게 줄어듦 |
| 필요할 때만 수집 | `collect_policy: when_needed` | 이미 모은 문서가 있으면 검색어 추출·수집 생략 → LLM 1회(답변)만 |
| 배경 수집 (권장) | `collect_policy: background` | when_needed처럼 바로 답하고, 이번 질문에 맞는 문서 수집은 뒤에서 → 다음 질문의 근거가 풍부해짐 |
| 같은 질문 저장 | `answer_cache: true` | 같은 감염병·같은 질문은 저장된 답(7일)으로 즉시 |
| 문서 미리 색인 | `python -m scripts.build_index --prefetch-docs` | 133개 감염병의 위키 문서를 미리 → **처음 묻는 질문도** LLM 1회 |
| 가벼운 보조 모델 | `aux_model: "gpt-4.1-nano"` 등 | 검색어 추출·후보 선별만 작은 모델로 (수집할 때만 영향) |
| 요약 LLM 끄기 | `summary_llm: false` | 오른쪽 요약을 답의 '핵심 답변'으로 → 질문당 LLM 1회 절약 |
| 답변 모델 변경 | `chat_model` | 모델마다 속도·품질이 다름 → `bench_chat --models`로 비교 |

## 3. 측정 결과

### 3-1. 모의 측정 (이 저장소의 작업 환경, 네트워크 없음)

GMS·위키백과에 접속할 수 없는 환경이라, 가짜 LLM·위키·임베딩에 흔한 지연(보조 LLM 1.0초, 답변 3.0초 중 첫 글자 0.7초,
위키 검색 0.5초, 본문 0.6초, 임베딩 0.3초)을 넣어 **흐름의 차이**만 쟀다. 숫자는 모의값이며, 호출 수는 실제 코드 그대로다.
가짜 위키에는 '홍역' 문서뿐이라 cold 수집량이 실제보다 적다(실제 cold는 LLM·위키 호출이 더 많아 차이가 더 커진다).

`python -m scripts.bench_chat --fake --ui`

| 설정 | cold 총 | cold 첫 글자 | warm 총 | warm 첫 글자 | 평균 | LLM 호출 cold/warm | 기존 대비 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| baseline | 6.87s | 6.87s | 4.32s | 4.32s | 5.60s | 3 / 2 | - |
| parallel | 5.97s | 5.97s | 4.32s | 4.32s | 5.14s | 3 / 2 | 8% 단축 |
| stream | 5.97s | 3.83s | 4.33s | 2.18s | 5.15s | 3 / 2 | 8% (첫 글자 44~50% 단축) |
| when_needed | 5.97s | 3.83s | 3.32s | 1.17s | 4.64s | 3 / 1 | 17% 단축 |
| background | 5.97s | 3.83s | 3.32s | 1.18s | 4.64s | 3 / 1 | 17% 단축 |
| cache (같은 질문 반복) | | | | | 0.00s | 0 | 즉시 |
| **prefetch** | 3.34s | 1.17s | 3.32s | 1.18s | **3.33s** | 1 / 1 | **41% 단축** |

- 첫 글자까지 기다리는 시간: 6.87s(기존 cold) → **1.17s**(prefetch), 4.32s(기존 warm) → **1.18s**.
- Streamlit 화면 자체가 더하는 시간: 질문당 **0.08초**(LLM 요약을 끈 뒤). 처음 측정 때 1.08초였는데, 원인은 화면이 아니라
  오른쪽 요약의 LLM 호출이었다 → `summary_llm: false`로 해결.
- 따라서 **Streamlit을 다른 수단(FastAPI+JS 등)으로 바꿔도 줄어드는 시간은 0.1초 미만**이다. 시간은 거의 전부 LLM·위키 호출에서 나온다.

### 3-2. 실제 측정 (각자 컴퓨터에서)

```bash
python -m scripts.bench_chat                                         # 설정 7가지 비교 (약 3~5분)
python -m scripts.bench_chat --models gpt-4.1-mini,gpt-4.1-nano,gpt-4o-mini   # 답변 모델 비교 (background 설정)
python -m scripts.bench_chat --configs baseline,background --aux-model gpt-4.1-nano   # 보조 모델
```

결과는 `reports/bench_chat.md`(표)와 `reports/bench_chat.json`(질문별 상세)에 저장된다.
측정은 지금 색인을 임시 폴더에 복사해서 하므로 실제 `data/chroma`·캐시는 바뀌지 않는다.

## 4. 선택한 기본값과 이유

| 설정 | 값 | 이유 |
| --- | --- | --- |
| `collect_policy` | `background` | warm 질문을 LLM 1회로. when_needed와 속도는 같고, 새 질문에 맞는 문서가 뒤에서 계속 쌓임 |
| `parallel_collect` | `true` | cold 수집 시간 단축, 결과는 순차와 같음(테스트로 확인) |
| `stream_answer` | `true` | 첫 글자 대기 시간이 가장 크게 줄어드는 방법 |
| `answer_cache` | `true` | 같은 질문 즉시. 프롬프트·모델이 바뀌면 자동으로 새로 만듦 |
| `summary_llm` | `false` | 요약을 '핵심 답변'으로 만들어 질문당 LLM 1회 절약 |
| `aux_model` | `""` | 실제 측정 전이라 바꾸지 않음. `--aux-model`로 비교 후 결정 |
| 문서 미리 색인 | 권장 | 한 번 실행(수 분)으로 모든 첫 질문이 warm이 됨 |

화면에는 답마다 `⏱ 3.2초 · 첫 글자 1.1초 · LLM 1회 (근거 검색 0.3 · 답변 2.9)`처럼 실제 걸린 시간이 표시된다.
